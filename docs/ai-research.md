## Synthesized design

# Challenger AI: "TurnPlanner" — deterministic beam search over the full 5-move turn, simulation-backed by the real engine, with a focus-target FFA policy and greedy-reply leaves

ONE primary design. Not MCTS (rollouts cost 5-60 ms each; deterministic engine + deterministic opponents means repeated sampling adds zero information at this budget). Not OEP/NTBOE first (that is v3 if the beam plateaus). The literature (Justesen 2016: Greedy Turn >> Greedy Action on Hero Academy, the closest analog) plus the measured costs (~90 us per `Engine.move`, ~10k sims/sec) make a candidate-pruned beam over the 5-action sequence the highest win-rate-per-engineering-hour choice, and Hex Empire's determinism makes every simulated line exact — lookahead pays off more here than in any published testbed.

## 1. Algorithm shape

Integration: implement the `HexEmpire.Engine.Ai` behaviour (`/Users/christophe/Documents/Code/javascript/hexempire/lib/hex_empire/engine/ai.ex`). On the first `play_action` of a turn (detect `turn_moves_spent == 0` or stale plan key `{party, turns}`), plan the WHOLE turn once, stash the move list in `game.ai_trace`, and serve one move per subsequent call, re-verifying each `(from, to)` against `Movement.possible_moves` (2.4 us) before applying. Nothing changes between your own 5 actions, so plan-once is exact.

Per-turn pre-computation (~2 ms, once):
- BFS distance field over the 220 fields from each enemy original capital, own capital, and the focus target's capital (respecting walk/port semantics). This replaces the baseline's ~12 ms/pass memoized A* and makes every static score O(1). Reuse `game.ring2` for support/threat rings.
- Combat oracle: pure functions replicating `combat.ex` exactly — win iff att.count+att.morale > def.count+def.morale (ties to defender); winner survivors = max(1, c_a − floor(D/A·c_a)); losing attack still deals floor(A/D·c_a) with the defender morale clamp (morale' ≤ count'); party-wide morale hit floor(loserCount/10). Golden-test it against `Combat.resolve/3` on 10k random army pairs.
- Focus-target selection (section 4) and capital-threat map (enemy power deliverable to own capital within 2 turns = armies within 4 hexes by distance field).

Search:
- Candidate generation per beam state: for each movable army, `Movement.possible_moves`; pre-score every (army, target) pair with a fast static scorer (distance-field gradient toward focus capital, oracle-verified attack outcomes, capture value, defense value, merge value); keep top M = 15 candidates, forced-diverse (at least one defensive and one capture candidate when they exist). Never propose an oracle-losing attack UNLESS it is tagged as a shave (a same-turn follow-up killer exists).
- Beam: depth ≤ 5 (the action budget), width W = 10, expand with `Engine.move` unmodified as the forward model (it is pure; `battle_luck: false` is the config default, so combat is bit-exact). ~750 `Engine.move` calls ≈ 100 ms. Include an explicit "stop here" candidate at every level so partial turns (banking morale, avoiding action-cap forfeits from merges) are searchable.
- Macro-injection (this is where the baseline is structurally blind): each turn, before the beam, enumerate all ordered 2- and 3-army combos against every enemy original capital and every enemy stack with power ≥ 150, using the oracle. Two 99-stacks kill a 99/99 garrison deterministically (wave 1 loses but clamps the defender to ~1/1; wave 2 kills) — the baseline can NEVER do this and can never defend against it. Inject any guaranteed decapitation or big-stack kill as a pre-built sequence seeding the beam. Likewise inject "capture town first, then the marginal attack" orderings (party-wide +10 morale applies mid-turn and flips fights) and "move blocker, then 2-hex strike".
- Leaf evaluation: take the top L = 8 end-of-turn states, apply end-of-turn, then simulate each living opponent's full reply with a FAST challenger-side reimplementation of the baseline greedy ranking using the cached distance fields (~5-10 ms/opponent; do NOT call `OriginalAi.rank_ai_armies` in the hot loop — it costs 60 ms/turn). Against the actual baseline this is a perfect opponent model (its policy is fully deterministic). Score the post-reply state with the eval below; argmax wins. v1 may model only the single most dangerous opponent (BRS-style) — that captures most of the value.
- Anytime budget: compute a greedy anchor plan first (~1 ms, complete 5-move fallback — never worse than baseline-shaped play), then run the beam with `:erlang.monotonic_time` deadline checks: ≤40% of budget on the beam, ≤50% on leaf replies evaluated best-first, 10% slack. Typical turn ~0.4-0.6 s; hard cap well under 1 s/action. No transposition table (rng/log fields and real move-order effects make hits rare and keys awkward). Single process first; `Task.async_stream` over leaves only if needed.

## 2. Evaluation function

Crucial architectural point: because leaves are REAL simulated states, morale cascades, neighbor-flip annexation, and capital-fall inheritance are already IN the state — the eval reads them, it never estimates them. That leaves ~7 scalar weights to tune instead of twenty. Unit of account = 1 troop-power. Score own party only (max^n).

- Material (most important): own Σ(count + morale) with weight +1.0; minus 0.6 × focus-target power, minus 0.25 × each other opponent's power. Morale is inside this term — do not double-count it.
- Income × horizon H = 8 turns: +8 per land, +40 per town, +40 per PORT (exact marginal is 5/turn — the baseline values ports at 3 vs towns at 5; ports are systematically cheap to take from it), +40 per held capital slot. Add +40 per enemy town/port denied (capture swing is double).
- Capital safety: −3.0 × max(0, enemy power deliverable onto own capital in ≤2 turns − (garrison power + ring2 friendly power)). This replaces any blanket garrison rule with a measured one; when threat is 0 the capital stack is free to fight.
- Offensive gradient: −5.0 × (distance of own strongest frontline army to focus capital). Pure shaping so 5-move turns that make no capture still make progress.
- Next-turn kill availability: +2000 if the oracle finds a guaranteed 1-2 wave combo onto an enemy original capital from the leaf position.
- Action/morale hygiene: −5 per own 99-count stack sitting on a producer hex (reinforcements clamp at 99 and are destroyed — 10+ucount income/turn wasted); +2 per movable army up to 5 (preserve the action cap); small −1 per army that will idle-decay.
- Feature importance order: (1) material via exact simulation, (2) capital/elimination events (mostly captured by simulation itself — inheritance deletes the victim's entire army list and hands you their territory, the single biggest swing in the game), (3) income×H, (4) capital safety, (5) gradient shaping. Tune only via tournament sweeps; do not hand-polish.

## 3. Forward model vs static eval

- `Engine.move` (`actions.ex`, pure, ~90 us): all beam expansions and injected macro-sequences. ~750-1500 calls/turn.
- End-turn + fast greedy reply policy: only at ≤8 leaves.
- Combat oracle (static, ~0.1 us): candidate pre-scoring and combo enumeration only — it filters, the engine decides.
- Cheap static eval: only for ORDERING candidates before expansion; every score that picks the plan comes from a simulated state. Do not build a "lite" forward model in v1 (the beam doesn't saturate 10k sims/s); it's a v3 optimization with golden tests if ever needed.

## 4. FFA target policy

Single focus target per turn with hysteresis, max^n at leaves, never paranoid (Nijssen & Winands; MP-Mix for the leader logic — Hex Empire is a high opponent-impact game, exactly where leader-aware switching pays):
- A(p) = w1/(frontline distance to p's original capital) + w2/total_power[p] + w3·leader_bias(p) + w4·opportunism(p) − w5·fortification(p). leader_bias fires only when total_power[p] > 1.5× second place, capped, never absolute (avoids kingmaking stagnation). opportunism = bonus when p's total_power fell over the last 3 turns (they're bleeding elsewhere); simultaneously up-weight neutral land/port expansion when two others are actively fighting.
- Hysteresis: keep the focus 3-5 turns unless its capital falls or another party exceeds 2× your power. Distance fields are computed for the focus capital; residual small weight toward other capitals so walk-in opportunities (any reachable UNDEFENDED enemy original capital = instant win-move; the baseline scores these only +20 and routinely ignores them) always register.
- Ratio gates in the pre-scorer: ordinary attacks require power ratio ≥ 1.4 (winner casualties ≈ count/r; fights are negative-sum in FFA); ratio ≥ 1.05 allowed only for capital-kill/elimination sequences; below gate, mass/merge scores higher.
- Losing policy: if own power < 0.4× every opponent, switch objective to survival — mass at capital, refuse morale-bleeding attacks, no spite terms ever.
- Mirror-match hygiene: when top-2 A(p) scores are within 10%, tie-break by seed-derived rotation so four challengers don't lockstep-dogpile.

## 5. What to build first, staged plan

Biggest single jump = v1's beam + decapitation scan. The baseline's two fatal blindspots — no multi-army same-turn combos (it cannot crack, or defend, a 99/99 with two waves) and empty-capital blindness — are both fixed by turn-level search with oracle-verified macros, no opponent modeling needed.
- v0 (day 1): combat oracle + golden tests vs `combat.ex`; BFS distance fields; plan-once `play_action` plumbing with `ai_trace` caching; fast static move scorer. Verify a trivial "greedy with distance fields" agent ties the baseline (sanity).
- v1 (days 2-3): depth-5 beam (W=10, M=15) with static eval at leaves (no opponent replies yet); decapitation/big-stack combo enumeration injected; undefended-capital walk-ins at +1e9 priority; focus-target gradient replacing max-over-all-capitals; ratio gates. Ship, measure. Expected: clearly >25% seat win rate, likely 45-65%.
- v2 (days 4-5): fast greedy-reply opponent model at leaves (perfect vs the deterministic baseline); measured capital defense sized to the exact worst 2-wave enemy combo (compute it — a challenger mirror CAN crack 99/99); morale hygiene (cycle garrisons off producers so spawns inherit faction morale; never camp 99 on a producer); opportunism/leader terms.
- v3 (next week, only if v2 plateaus or for mirror-vs-mirror strength): NTBOE or OEP over the 5-slot turn genome drawing genes from the same pruned candidate lists with the same leaf eval (~2-10k evals fits budget); optionally EMCTS-style sequence mutation. Also the lite forward model if profiling demands it.

## 6. Risks, failure modes, measurement

Risks: (a) Overfitting to the baseline's determinism — the perfect opponent model is a crutch; keep v1 strong WITHOUT replies so strength doesn't collapse vs non-baseline opponents, and run mirror matches. (b) Depth-5 horizon myopia — mitigated by capital-safety and kill-availability leaf terms. (c) Eval double-counting morale (it is inside power) — unit-test eval invariants. (d) Time blowups late game (23 armies, 266 pairs) — anytime deadline + greedy anchor makes worst case baseline-shaped, never a timeout. (e) Action-cap forfeits from merges — the engine re-caps after every `spend_action`; the "stop here" candidate plus the +2-per-movable-army term handles it, add a regression test. (f) Benchmark validity: `difficulty > 5` makes the baseline near-pacifist (−250 vs all non-human armies when human = −1); benchmark at difficulty 5 (the default) or results are inflated. (g) Draw inflation from over-cautious play — watch avg_rounds and the 3000-step cap.

Harness: the needed tool already exists — `HexEmpire.Engine.Tournament` (`/Users/christophe/Documents/Code/javascript/hexempire/lib/hex_empire/engine/tournament.ex`): seat-rotated (4 games/seed, challenger in each seat vs 3× `OriginalAi`), reproducible seeds, parallel via `Task.async_stream`, Wilson 95% intervals built in. Protocol: fix a committed list of 100 seeds → 400 games per configuration; run the all-baseline configuration once on the same seeds for the per-seat advantage table (seat advantage is real — always compare per-seat, as the moduledoc says). At 400 games the Wilson 95% CI is roughly ±4-5 points around 25-60% win rates: a challenger must clear ~31-32% overall to be significantly better than the 25% null at 95%; the v1 target is ≥45%, v2 target ≥60%. Because seeds are paired across configurations, use a per-(seed, seat) sign/McNemar test between successive versions for extra power at 100-400 games. Also record draws (nil winner) and avg_rounds per version, and assert per-action wall time < 1 s in the test suite. Every change re-runs the identical seed list; never tune weights and evaluate on the same seed split.


## Research: Literature review: turn-based strategy AI for multi-action turns (5 moves/turn, deterministic combat, perfect info, 4-player FFA) applicable to Hex Empire

CLOSEST DOMAIN MATCH: Hex Empire's turn structure (pick 5 of N armies, each with ~6-15 reachable targets => per-action branching ~100-500, per-turn ~10^10-10^12, intra-turn order matters via merges/captures) is almost exactly the "multi-action adversarial game" setting studied on Hero Academy and card games — that literature transfers more directly than RTS or Civ literature.

1) GREEDY BASELINES AND GREEDY-TURN / BEAM SEARCH. Justesen, Mahlmann & Togelius, "Online Evolution for Multi-Action Adversarial Games" (EvoApplications 2016, [PDF](http://julian.togelius.com/Justesen2016Online.pdf), [TCIAIG extension](https://sebastianrisi.com/wp-content/uploads/justesen_tciaig17.pdf)) formalizes the baselines: "Greedy Action" = 1-ply per-action argmax (this is what original_ai.ex is, plus its re-rank-after-every-move loop and wait-for-support hack), "Greedy Turn" = depth-first search over complete 5-action sequences with a state evaluation at end of turn. Greedy Turn clearly beats Greedy Action; both are beaten by evolutionary planning. Beam search over the 5-action sequence is the standard engineering version of Greedy Turn (prune to top-K candidate actions per ply, keep top-B partial sequences); no dedicated famous paper, but it is the de-facto shipped technique and the cheapest step up from 1-ply greedy. Togelius's summary ([blog](https://togelius.blogspot.com/2016/03/a-way-to-deal-with-enormous-branching.html?m=1)) stresses that vanilla MCTS collapses at these branching factors.

2) ONLINE EVOLUTIONARY PLANNING (OEP) / RHEA FAMILY. OEP (same papers): genome = the sequence of 5 atomic actions in one turn; fitness = evaluation of resulting state; mutation/crossover repair illegal genes. On Hero Academy OEP beat vanilla MCTS, Bridge-Burning MCTS, Greedy Action and Greedy Turn "by a large margin." Rolling Horizon EA generalization (Gaina et al., [RHEA in GVGP](https://arxiv.org/pdf/2003.12331), [PhD thesis](https://rdgain.github.io/assets/pdf/papers/gaina2021phd.pdf)): RHEA ≥ MCTS across many games, works best with macro-actions/coarse actions, but is MORE sensitive to opponent-model accuracy than MCTS — relevant because a 4p FFA gives 3 opponent turns between your turns. Engineering cost: low-medium (needs only forward model + eval + genome repair). Expected strength vs greedy: large (documented on the closest analog game).

3) EVOLUTIONARY MCTS (EMCTS) — CURRENT BEST ON HERO-ACADEMY-LIKE GAMES. Baier & Cowling, "Evolutionary MCTS for Multi-Action Adversarial Games" (CIG 2018, [IEEE](https://ieeexplore.ieee.org/document/8490403/)): tree nodes are COMPLETE turn sequences, edges are mutations of one action in the sequence; MCTS statistics guide which mutations to explore. Convincingly outperformed OEP, vanilla MCTS, BB-MCTS and greedy baselines; Flexible-Horizon EMCTS ([AIIDE 2019](https://ojs.aaai.org/index.php/AIIDE/article/view/13023)) extends the sequence past turn boundaries. NTBOE (Montoliu et al., [CEUR 2022](https://ceur-ws.org/Vol-3305/paper3.pdf)) is a cheaper alternative: one N-Tuple-bandit (NTBEA) model over the 5 gene slots of a turn — very sample-efficient (competitive around ~1000 forward-model evaluations), designed exactly for multi-action adversarial games. Engineering: medium. Strength: state of the art for this turn structure at small budgets.

4) CMAB / NAIVE SAMPLING / PER-UNIT MCTS DECOMPOSITION. Ontañón, "Combinatorial Multi-Armed Bandits for Real-Time Strategy Games" (JAIR 2017, [arXiv](https://arxiv.org/pdf/1710.04805)): NaiveMCTS assumes turn value ≈ sum of per-unit contributions; keeps one local MAB per unit plus a global MAB over sampled full combinations; dominates UCT variants in microRTS once units > ~8. Alternative decomposition: MCTS_u (fixed unit ordering, one unit-action per tree level — deeper, narrower tree), used in Elastic MCTS with state abstraction for strategy games (Xu et al., [IEEE ToG 2023](https://www.tnt.uni-hannover.de/papers/data/1675/_2023__IEEE_TOG__Elastic_Monte_Carlo_Tree_Search.pdf)); also Roelofs' thesis on [action-space representation in CMABs](https://project.dke.maastrichtuniversity.nl/games/files/msc/Roelofs_thesis.pdf) (dimensional vs hierarchical expansion). Fits 10-40 units on 220 hexes well; engineering: medium-high; strength: strong in RTS benchmarks, but rollout cost in Elixir will force eval-cutoff rollouts (1-2 turn horizon) rather than play-to-end.

5) SCRIPTED-PORTFOLIO SEARCH. Churchill & Buro, "Portfolio Greedy Search and Simulation for Large-Scale Combat in StarCraft" (CIG 2013, [ResearchGate](https://www.researchgate.net/publication/261527070_Portfolio_greedy_search_and_simulation_for_large-scale_combat_in_starcraft)): search over per-unit ASSIGNMENT OF SCRIPTS (attack-weakest, kite, etc.), hill-climbing one unit at a time against the opponent's assumed assignment; scales to 50+ units where alpha-beta/UCT fail outright. Successors: Portfolio Online Evolution and portfolio-CMAB hybrids in microRTS beat PGS. Portfolio ideas reduce Hex Empire's action space to ~5-8 semantic behaviors per army (march-on-capital-X, take-town, defend-capital, merge/consolidate, garrison-port, harass-weakest) — note the existing wait-for-support mechanic is a hand-rolled 2-script portfolio. Engineering: low-medium (scripts are easy given existing pathfinding); strength: large and very robust per unit of compute; best option if you want coordinated multi-turn behavior without deep search.

6) 4-PLAYER FFA SEARCH POLICY. Nijssen & Winands ([PhD thesis](https://project.dke.maastrichtuniversity.nl/games/files/phd/Nijssen_thesis.pdf), [overview](https://dke.maastrichtuniversity.nl/pim.nijssen/pub/cgw.pdf)): in MCTS, max^n-style backprop (each player maximizes own utility) is overall best for multiplayer; paranoid and Best-Reply Search help mainly in minimax settings or at small budgets. Practical consequence: never assume a 3-player coalition against you; evaluate own utility, and model opponents with a cheap policy. Hex Empire has a unique asset here: the deterministic scripted OriginalAi is a ready-made, exact opponent model for lookahead — literature (RHEA opponent-model sensitivity, above) says search quality improves a lot with a decent opponent model, and here the default opponents literally ARE that model.

7) WHAT SHIPS IN COMMERCIAL/OSS 4X: DEEP GREEDY + STRONG EVAL, NOT SEARCH. Battle for Wesnoth: RCA ("Rating Candidate Actions") AI — rule-based candidate actions each self-score, highest executes, repeat ([RCA AI](https://wiki.wesnoth.org/RCA_AI), [AOSA chapter](https://aosabook.org/en/v1/wesnoth.html)); combat handled by cached fight simulation (compare_unit_types), recruitment CA finds "important hexes" and simulates matchups ([AI Recruitment](https://wiki.wesnoth.org/AI_Recruitment)). Civilization III/IV (Soren Johnson, [GDC 2008 "Playing to Lose"](https://archive.org/details/GDC2008Johnson2)): soft-coded weighted evaluation of effects, per-unit greedy tactical decisions over influence/danger maps — no combinatorial turn search; same for Old World. Polytopia research clone Tribes (Perez-Liebana et al., AIIDE 2020, [paper](https://rdgain.github.io/assets/pdf/papers/perez2020tribes.pdf), [GitHub](https://github.com/GAIGResearch/Tribes)): baseline MC/MCTS/RHEA agents; follow-up ([MCTS pruning in Tribes](https://gaigresearch.github.io/2020/06/15/hsu2020mcts/)) showed MCTS needs aggressive pruning + injected domain knowledge to beat rule-based agents, and then outperforms RHEA. Lesson: with a ~1s budget, eval-function quality and candidate pruning dominate algorithm choice.

BUDGET REALITY CHECK: Elixir immutable-map state => expect roughly 10^4-10^5 five-move turn simulations/sec if the eval is O(fields) and incremental where possible. That budget comfortably fits beam search, OEP/NTBOE (~10^3-10^4 evals), PGS, and shallow EMCTS; it does NOT fit vanilla MCTS with play-to-end rollouts. Deterministic combat + perfect information means every simulated line is exact — lookahead pays off more here than in stochastic testbeds (Tribes, Blood Bowl), strengthening the case for turn-level search over pure heuristics.

### Recommendations

Build in this order; each tier is a strict strength upgrade over the 1-ply greedy in original_ai.ex and stays within ~1s/action on one core.

STEP 0 (prerequisite for everything): a turn-level forward model + static evaluation function. Simulate applying a full 5-move sequence (exact — combat is deterministic), then score: material (sum count+morale), income (5/capital + per-city 5+floor((lands+5*ports)/cities) — ports are worth 5 lands, eval must know this), morale economy (faction average feeds recruit quality — penalize morale-bleeding attacks), capital safety (distance-weighted enemy power vs garrison, using existing Pathfinding), and capital-capture expected value weighted by INHERITED TERRITORY (the winner-takes-all-land rule makes finishing a weakened player the single biggest swing in the game — encode it explicitly). Reuse ring2/pathfinding memos from original_ai.ex.

TIER 1 (days of work, expected large win-rate gain — Justesen's Greedy Turn >> Greedy Action result): beam search over the 5-action turn. Candidate pruning per state: top ~10 armies by relevance (near frontier/capitals/threats), top ~4 targets per army scored by the existing score_move; beam width 100-300 over depth 5; evaluate leaf states with Step 0 eval after adding a 1-ply opponent-threat estimate (what can each enemy hit next turn — computable exactly). This fixes greedy's two blind spots: move-order coordination (soften-then-kill on one hex, merge-then-attack) and 5-move allocation across fronts.

TIER 2 (about a week): NTBOE or OEP over the turn genome. Genes = 5 slots of (army, target) drawn from the pruned candidate lists; fitness = Tier-1 leaf eval; ~2000-10000 evaluations per turn fits the budget. Literature (Hero Academy) says this beats both greedy-turn and MCTS at these branching factors; NTBOE is the most sample-efficient published option.

TIER 3 (stretch): shallow adversarial lookahead. After your simulated turn, play each opponent's intervening turn with the existing OriginalAi as the exact opponent model (it is the actual opponent in-game — a luxury the literature never has), then re-evaluate; wrap in EMCTS (mutate the turn sequence, MCTS over mutations) or MCTS_u with max^n backprop if you want 2+ turn horizons. Do NOT use paranoid search — 4p FFA + max^n is the robust choice (Nijssen & Winands); do not attempt play-to-end rollouts.

ORTHOGONAL, HIGH VALUE: a portfolio layer (PGS-style) for armies NOT selected as one of the 5 movers and for strategic coherence — scripts: march-on-capital(p), capture-towns, defend-own-capital, consolidate/merge, garrison-port, finish-weakest-player. Search assigns scripts per army; scripts generate the candidate moves fed to Tiers 1-2. This replaces the fragile wait-for-support global-flag mechanic with principled coordination and keeps branching flat as army count grows past ~15.

FFA-specific eval guidance: score only your own utility (max^n style); add explicit terms for (a) inherited-territory EV of each capital kill, (b) not over-extending against the current leader while two others fight (the +200 "gang up on the strong same-side player" hack in score_move is a crude version — generalize via total_power ratios), (c) morale snowball: prefer strings of cheap captures before big fights since capture morale is nation-wide (+10/city) and defeats bleed the whole faction.

Benchmark harness: the deterministic engine + seeded RNG (rng.ex) makes round-robin self-play trivial — run challenger vs 3x OriginalAi over ~200 seeded maps per change; the literature's effect sizes (Greedy Turn vs Greedy Action, OEP vs Greedy Turn) predict each tier should be measurable at that sample size.


## Research: game-structure: exploitable structure in the Hex Empire engine (combat math, economy, morale, liberation, turn mechanics) and concrete weaknesses of the baseline greedy AI

== 1. COMBAT IS EXACTLY PREDICTABLE (combat.ex; battle_luck defaults to false in config.ex) ==
Let A = att.count + att.morale, D = def.count + def.morale (luck = 0 by default).
- Attacker wins iff A > D (TIES GO TO DEFENDER — you need strictly greater power).
- If attacker wins: survivors = max(1, att.count - floor(D/A * att.count)); att.morale' = min(att.morale, survivors); defender annihilated; EVERY army of defender's party loses floor(def.count/10) morale (pre-battle count, stale army list).
- If defender wins: def.count' = max(1, def.count - floor(A/D * att.count)); def.morale' = min(def.morale, def.count'); attacker annihilated; attacker's party takes floor(att.count/10) morale party-wide.
Key consequences an evaluator can use exactly:
- LOSING attacks still deal floor(A/D * att.count) casualties — a near-equal-power "kamikaze" trades troops almost 1:1 AND the morale clamp (morale' <= count') often collapses the defender's power far below D. Worked example: defender 99/99 (198). Wave 1: 99/98 (197) attacks and LOSES, but defender drops to count = 99 - floor(197/198*99) = 1, morale clamped to 1 → power 2. Wave 2: anything kills it. Two 99-stacks kill a maxed 99/99 capital garrison in one turn, guaranteed.
- Winner casualties scale with D/A × att.count: morale is "free" power that both wins fights and reduces casualties; small high-morale armies take casualties proportional to their own small count → elite stacks are cheap to fight with.
- The baseline AI can NEVER kill a 99/99 garrison via its capital branch (needs single-army strict power > 198, max possible is 198 = tie = defender wins). A 99/99 capital garrison is permanently immune to the baseline's guaranteed-kill logic but dies to any 2-wave combo.

== 2. ECONOMY — EXACT MARGINAL VALUES (reinforcements.ex, state.ex update_derived) ==
ucount = floor((|lands| + 5*|ports|) / max(1,|towns|)); each town spawns 5 + ucount; every held capital field spawns +5 (capitals are also towns per generator.ex line ~135, so a held capital yields 10 + ucount). ports_generate_troops is false by default: ports do NOT produce locally but add 5 to the numerator.
Total income/turn ≈ 5*capitals_held + 5*T + L + 5*P (minus rounding loss (L+5P) mod T per turn). Marginal values in troops/turn: plain land hex = +1, port = +5 (equal to a town!), town = +5 (plus spawn-point placement), capital slot = +5. Capturing an enemy town is a +10/turn swing (their -5, your +5); same for ports.
Annex neighbor-flip (territory.ex): capturing one hex flips all adjacent empty, estate-less land hexes to you — one move can annex up to 6 extra lands, each worth +1/turn AND +1 party-wide morale.
99-cap waste: Army.join clamps at 99 (army.ex) — reinforcements into a full stack are silently destroyed. A capital camping at 99 wastes 10+ucount troops/turn.
Recruit morale rule: spawns onto an EMPTY producer use faction morale; onto an existing garrison use THAT army's (often decayed) morale. Cycling garrisons out before turn end makes new spawns inherit the (higher) faction average.

== 3. MORALE ARITHMETIC & SNOWBALL (morale.ex, territory.ex) ==
Party-wide awards on capture: recapture own capital {+50 all, +30 self}, enemy capital {+30,+20}, town {+10,+10}, port {+5,+5}, land {+1,0}; each neighbor-flipped hex awards again (+1 each). Former owner's party takes -30 (capital), -10 (town), -5 (port) party-wide. Combat loss costs the loser's party floor(loserCount/10) everywhere.
Power value of morale: each +1 party-wide = +1 power on every army with headroom (morale ≤ count). With ~12 armies, one town capture = up to +120 total board power, immediately. Faction morale = floor(avg army morale); refresh_faction gives a floor of floor(totalCount/50). Idle (unmoved) armies decay -1 morale/turn (state.ex cleanup_turn) — morale is use-it-or-lose-it, and enemy garrisons that never move decay toward 0 morale, making stale garrisons soft targets.
Break-even calculus is exact: a capture is worth (award_all × #own_armies_with_headroom + award_self) + income swing/turn × horizon − expected casualties − enemy's symmetric loss penalty.
CRITICAL SEQUENCING FACT: morale awards apply immediately and party-wide mid-turn. Capture a town with army A first, and army B gains +10 power BEFORE its attack the same turn — this can deterministically flip B's attack from loss to win (e.g. 90/80=170 vs 99/76=175 loses; after a town capture 90/90=180 wins).

== 4. CAPITAL FALL, INHERITANCE, LIBERATION (territory.ex do_annex, state.ex update_derived) ==
When a faction's original capital falls, update_derived sets every field occupied by that faction to the heir (capital's new owner) AND DELETES ALL ITS ARMIES (army: nil). Decapitation = annihilate their whole military + inherit all territory in one blow — worth nearly any sacrifice; value ≈ their total_count + their entire income base.
Liberation: province_capitals[p] = capitals held by p whose ORIGINAL faction has zero armies. When p's own original capital falls, each such capital reverts to its original faction with a fresh 99/99 army (startup annex, neighbor flips). Tempo play: decapitating a leader who holds dead factions' capitals resurrects those factions as 99/99 armies in the leader's rear — you gain the leader's land, and the resurrected factions harass everyone else. Conversely, when YOU hold captured capitals, your own capital is a single point of catastrophic failure. Note: directly capturing an enemy-HELD captured capital does NOT liberate anyone — it just becomes yours ({+30,+20} morale) and counts toward the sole-controller victory check.

== 5. TURN STRUCTURE (movement.ex, actions.ex, state.ex) ==
5 actions/turn, capped at min(5, movable armies) at begin_turn AND re-capped after every spend_action — merging your 5th and 4th armies can forfeit an action. Each army moves once (moved flag); merge marks the TARGET stack moved (merge-then-attack impossible; attack-then-reinforce-behind is). 2-hex moves require the intermediate hex to be empty, non-estate land (can_continue?) — towns, ports and any army block transit; move blockers first to open lanes. Ports are the only sea gateways (step_allowed?). Merges: weighted-average morale; overflow above 99 splits a leftover on the origin.
Ordering combos that matter (all exactly computable): (a) shave-then-kill two-wave attacks; (b) capture-for-morale before a marginal attack; (c) unblock a lane, then 2-hex strike; (d) merge leftovers to preserve next turn's action cap.

== 6. BASELINE AI WEAKNESSES (original_ai.ex — all deterministic, all exploitable) ==
(a) Empty-capital blindness: the +1e6 capital-kill bonus requires field.army != nil AND single-army strict power win. An UNDEFENDED enemy original capital scores only +20 — routinely outranked by the +1000 defend-own-capital and +200 gang-up bonuses. A challenger should treat any reachable undefended capital as an instant win-move.
(b) No combat simulation anywhere except that one capital check: it happily attacks stronger defenders (losing armies + party-wide morale) and never plans multi-army same-turn combos.
(c) Ports undervalued (+3) vs towns (+5) despite identical +5/turn income; plain land worth ~0 except the near-town +3 — it under-fights for economy.
(d) Capital camping: after turn 5, moving off own capital gets -1000 → its capital stack sits forever, hits 99, and wastes 10+ucount income/turn while its garrison morale never refreshes from faction average.
(e) wait-for-support stall: it freezes its best attack for up to 5 ranking passes when ring-2 friendly power < ring-2 enemy power (and < 300), or its army is weaker than the defender (count < 90), unless target is near its capital or a guaranteed capital kill. Parking one visible big stack in ring-2 of its staging area paralyzes it; the "supporter" substitution then funnels other armies toward a predictable clump you can pre-target.
(f) difficulty > 5 applies -250 to attacking any non-human army — in spectator/AI-vs-AI games (human = -1) that is EVERY occupied field: on hard, the baseline is globally attack-averse. Also +difficulty*2 gradient bias toward the human's capital makes its routing predictable.
(g) Fully deterministic policy (stable sorts, lexicographic tie-breaks, no gameplay RNG with battle_luck off): perform_fast_ai_turn on a copied state reproduces the opponent's ENTIRE next turn exactly. Perfect opponent modeling is available for free.
(h) It always spends all actions (never passes strategically) and its gradient (-A* path length toward enemy-held original capitals, pathfinding.ex) plus tiny bonuses means late-game moves are wasted on +1 land drift instead of consolidation or defense of towns.

### Recommendations

1. Build an exact combat oracle first (pure functions of the two armies): win = A > D; att_survivors = max(1, c_a - floor(D/A*c_a)); losing-attack damage = floor(A/D*c_a) with defender morale clamp; party-wide morale deltas floor(loserCount/10). This makes every candidate attack, two-wave combo, and trade ratio exactly evaluable at 1 ply — no search noise, no estimation.

2. Turn planner = small sequenced-combo search over the 5 actions, not 5 independent greedy picks. Prioritized combo templates keep it cheap: (a) shave-then-kill on capitals/big stacks (two 99-stacks beat 99/99 guaranteed); (b) capture town/port first for the immediate party-wide morale boost, then re-evaluate marginal attacks with the new morale; (c) move blockers to open 2-hex lanes before strikes; (d) preserve ≥5 movable stacks so the action cap never shrinks. Enumerating ordered pairs/triples of (army, target) with the oracle prunes to well under 1s.

3. Decapitation-first strategy: each turn, test every enemy original capital against all 1-3 army reachable combos. Value a kill at (their total_count + full income base + liberation side-effects); accept large sacrifices. Symmetrically: always hold your own capital at 99/99 or with ring-2 support exceeding any enemy 2-wave combo (compute it exactly — the baseline can never crack 99/99, but a challenger-vs-challenger mirror can).

4. Economic evaluator with the exact marginals: land +1/turn, port +5/turn, town +5/turn, capital +5/turn, plus neighbor-flip annexation counting (a single capture can be worth +5-7 lands and morale). Value ports as full towns (the baseline won't defend them proportionally — take them). Convert morale swings to power via (delta × #own armies with morale headroom) and add income × a ~5-10 turn horizon.

5. Anti-baseline tactics: walk into any undefended capital immediately (it won't rush yours back optimally); freeze its offense by keeping ≥ its ring-2 friendly power visible near its staging hexes (wait-for-support stall, 5-turn lockout); in AI-vs-AI benchmarks note difficulty>5 makes it near-pacifist (-250 on all occupied targets) — benchmark at difficulty ≤5 for a fair baseline.

6. Exploit determinism for 2-ply search: clone the state and run OriginalAi.perform_fast_ai_turn + State.finish_turn to get each opponent's EXACT reply to any candidate plan. Even simulating only the strongest opponent's full turn per candidate plan gives perfect one-step lookahead against the baseline within the seconds-per-turn budget.

7. Hygiene rules from the mechanics: cycle garrisons off producer hexes so spawns inherit faction morale instead of decayed garrison morale; never let stacks idle at 99 on producers (income is destroyed by the clamp); spend high-morale armies before decay erodes them; when holding captured capitals, over-garrison your own capital because its fall both transfers everything and resurrects dead factions behind you.


## Research: ffa-dynamics: 4-player free-for-all target selection, kingmaking, multi-front threat assessment for the Hex Empire challenger AI

LITERATURE (named algorithms/papers):
1. Multiplayer tree-search family: MaxN (Luckhardt & Irani 1986; each opponent maximizes own component) vs Paranoid (Sturtevant & Korf 2000; all opponents form a coalition vs you) vs Best-Reply Search (BRS, Schadd & Winands 2011). BRS lets ONLY the single opponent with the strongest counter-move reply at each opponent layer, so the root player gets far deeper effective lookahead; BRS beat MaxN in all tested games (Chinese Checkers, Focus, Rolit) and beat Paranoid in 2 of 3. Sturtevant's "A Comparison of Algorithms for Multi-player Games" found neither MaxN nor Paranoid dominates — it is game-dependent; MCTS variants work best with the MaxN tree structure (Nijssen & Winands, Maastricht overview).
2. MP-Mix (Zuckerman, Felner, Kraus 2009; evaluated on Hearts, Risk, Quoridor): dynamically switch propagation strategy by leader margins — use a "directed offensive" strategy (everyone gangs the leader) when some opponent's lead exceeds a defensive threshold, switch to Paranoid when YOU lead by more than a threshold (expect to be ganged), otherwise plain MaxN. MP-Mix significantly outperformed fixed MaxN and fixed Paranoid, and its benefit grows with the "Opponent Impact" factor — how much players can directly hurt each other. Hex Empire (armies destroy each other, capital capture transfers a whole empire) is a HIGH opponent-impact game, exactly the regime where leader-aware strategy switching pays.
3. Risk AI heuristics (Hahn, Maastricht bachelor paper "Evaluating Heuristics in the Game Risk"; kengz/Risk-game strategy notes; KERAIA rule-bot comparisons): rule bots tested "attack weakest" vs "attack strongest"; consistent findings: (a) near-dead players get prioritized by everyone (elimination bonus / fewer enemies), (b) pure "attack strongest" bots bleed themselves while the third player profits, (c) continent/economy consolidation (compact territory, few borders) beats raw aggression. Practical Risk bots gate attacks on force ratios and count of exposed borders.
4. Kingmaking / "Beat the Leader" design literature (DiVA thesis "Mitigating Kingmaking in Multiplayer Board Games" + game-design commonplace): if all AIs deterministically dogpile the leader, the game stagnates and second place is effectively kingmade; if none do, the leader snowballs. Practical fielded scheme in FFA games: a MIXED target policy — e.g., one shipped game uses 25% attack-the-leader / 25% attack-the-weakest / 25% attack-nearest / 25% random — softly punishing the leader without lockstep coalitions. The AI-design fix for kingmaking on the AI's own side: optimize expected PLACEMENT/win-probability, never "damage dealt to X", so a doomed bot turtles for survival instead of spitefully deciding the winner.
5. No-press Diplomacy (DipNet, Paquette 2019; SearchBot, Gray et al. 2020 "Human-Level Performance in No-Press Diplomacy via Equilibrium Search"; DORA, Bakhtin 2021): the decisive upgrade over greedy/imitation policies was 1-2 step equilibrium/rollout search over a SMALL candidate move set (~50 joint moves) with a cheap value function (supply-center count local reward + terminal reward). Lesson transferable at tiny scale: you don't need deep search — scoring a handful of candidate moves against the most dangerous enemy reply (BRS-style) already captures most of the gain.
6. Catan MCTS (Szita, Chaslot, Spronck 2009 "Monte-Carlo Tree Search in Settlers of Catan"): flat heuristic bots lose to even shallow MCTS; robber (attack) placement handled with simple leader-biased bonuses — mirrors the "small leader bias inside an otherwise economic policy" pattern.
7. FFA strategic folk-theorems that survive contact with these papers: (i) fights are negative-sum for the two participants — third parties gain relative strength, so only take fights at lopsided ratios or for decisive objectives; (ii) opportunism beats initiative — attack the player currently engaged elsewhere (their army is committed, their power delta is negative); (iii) expand into neutral territory before contesting contested territory; (iv) focus-fire one victim to elimination rather than poking two fronts, BUT keep home defense sized to the fastest enemy reach.

BASELINE-SPECIFIC OBSERVATIONS (/Users/christophe/Documents/Code/javascript/hexempire/lib/hex_empire/engine/original_ai.ex):
- The greedy scorer takes max over ALL enemy capital gradients per move (line ~188): armies naturally split toward two capitals on two fronts and oscillate as gradients tie — the classic multi-front dilution failure.
- It already contains a crude balance-of-power term: +200 for attacking an army whose party's total_power > 1.5x yours (restricted to same board half, lines 236-241) and an anti-human bias (difficulty*2 on the gradient toward the human's capital). So "attack the leader" exists but only fires on adjacent-army contact, not in strategic routing.
- Wait-for-support is threshold-based (friendly_power < 300, count < 90), not ratio-based; combat math (winner loses floor(loserPower/winnerPower × attackerCount)) means an attack at ratio r costs you ~count/r troops — at r≈1.1 you nearly wipe yourself even when you win, a disaster in FFA where the two bystanders keep full strength. At r≥2 the fight is cheap.
- Capital-fall inheritance (winner takes ALL of loser's territory) makes elimination the single highest-value event in the game — far more so than in Risk — so victim selection + capital snipe timing dominates everything else.
- Capital garrison logic is a blanket -1000 for moving off own capital after turn 5: no actual threat measurement, so it over-garrisons when safe and can't surge-defend when three enemy stacks are 2 turns away.

### Recommendations

Ranked, concrete, all within the ~1s/action budget:
1. SINGLE FOCUS TARGET PER TURN (biggest single win — the literature's "simple policy that most improves a greedy AI" is focus-fire on the best expected-value victim, softly modulated by leader bias). Once per turn, pick one enemy party p maximizing attackability: A(p) = w1/(my_frontline_distance_to_cap(p)) + w2*(1/total_power[p]) + w3*leader_bias(p) − w4*fortification(cap garrison + nearby power), where leader_bias(p) kicks in only when total_power[p] > ~1.5x second-place (MP-Mix threshold style — soft bonus, capped, never an absolute override, to avoid the stagnation/kingmaking failure mode). Then compute the capital gradient ONLY toward the focus target's capital (keep a small residual weight on others so opportunistic grabs still register). Add hysteresis: keep the focus 3-5 turns unless its capital falls or a new party's power exceeds 2x mine. This converts two-front dithering into elimination pressure, and elimination is the jackpot in Hex Empire because of territory inheritance.
2. RATIO-GATED COMBAT instead of the flat wait-for-support thresholds: require attacker_power ≥ ~1.4 × defender_power for ordinary attacks (cost ≈ count/r is then tolerable); allow ratio ≥1.05 only for capital-kill or elimination moves; below the gate, score merging/massing higher (reuse the existing supporter machinery but drive it by the ratio, not the <300 constant). This directly encodes "fights are negative-sum in FFA — only take lopsided ones."
3. OPPORTUNISM TERM: track each party's total_power delta over the last 2-3 turns (total_power is already maintained). Add a bonus to gradients/attacks toward a party whose power is falling (they're bleeding against someone else) and a small malus for initiating fresh contact with a party at full strength while two others are actively fighting — during that window, weight neutral-land/port expansion up (income formula 5 + floor((lands+5*ports)/cities) makes ports/land grabs compound).
4. MEASURED CAPITAL DEFENSE replacing the blanket -1000: per turn compute threat = Σ over enemy armies within ~4 turns' reach of power/(turns_to_reach) using the existing pathfinding (memoized like capital_gradient). Required garrison ≈ max enemy power deliverable in 2 turns (they get 5 moves × 2 hexes). If garrison+ring2 friendly power < threat, boost scores of moves toward home; if threat ≈ 0, free the capital stack fully — no turn-5 constant.
5. CHEAP LOOKAHEAD IF BUDGET ALLOWS: BRS-style 2-ply — for each of the top ~10 candidate moves from the greedy ranking, simulate only the single strongest enemy reply within reach of the destination (not all three opponents — that's the whole point of BRS) and re-score. This is the highest-value search upgrade per CPU cycle per Schadd & Winands, and fits Elixir single-core easily since combat is deterministic.
6. LOSING-POSITION POLICY (kingmaking hygiene): if my total_power < ~0.4x of every opponent, switch objective from gradient-to-enemy-capitals to survival: mass on/near capital, preserve morale (avoid idle decay by shuffling, avoid hopeless attacks that cost party-wide morale -loserCount/10). Never add any "hurt the player who killed my cities" spite term — utility must stay placement/survival-based.
7. Keep a small stochastic or mixed element in focus-target choice when A(p) scores are within ~10% (e.g., deterministic tie-break rotation seeded from the game RNG), mirroring the shipped 25%-mix pattern — prevents four copies of the challenger from lockstep-dogpiling one party in self-play and makes it less exploitable by the human.
Priority order for implementation/testing vs the baseline (original_ai.ex is the benchmark opponent): 1, 2, 4 first — they are pure scorer edits reusing existing pathfinding/ring2 plumbing; then 3; 5 and 7 last.


## Research: budget-arch: compute architecture for the Hex Empire challenger AI (Elixir/BEAM, ~1s per action)

MEASURED COSTS (mid-game state, turn 8-26, seed 123456, mix run on this machine; engine at /Users/christophe/Documents/Code/javascript/hexempire/lib/hex_empire/engine/):
- Movement.possible_moves per army: 2.4 us; avg branching ~11 targets/army (range 6-18).
- Engine.move (Actions.move_army + spend_action, the full pure forward model): ~85-100 us/move. Of that, State.update_derived is ~77 us — it is the dominant cost (rebuilds armies/towns/ports/lands lists over all 220 fields with List.update_at and `++` appends, called once per move via Territory.annex_land path in actions.ex).
- "Cloning" is free: %{game | ...} = 0.1 us; Map.put into the 220-entry fields map = 0.1 us (HAMT, copies ~log32 path only). Game struct unique heap size ~20k words (~160 KiB) but persistent updates share almost everything; memory is a non-issue for thousands of live simulated states.
- Baseline OriginalAi.rank_ai_armies (one greedy ranking pass): ~11-12 ms; full ai_turn ~60 ms. Nearly all of it is Pathfinding.find_path (linear-scan A*, per (candidate-field, enemy-capital), memoized only within one pass — ~100+ calls x ~100 us).
- Branching per position: 98 (army,target) pairs mid-game (9 movable armies), 266 late-game (23 armies). Simulating EVERY pair once with Engine.move: 9 ms / 27 ms.
- Throughput budget: at ~100 us/simulated move, 1 s buys ~10,000 forward-model applications; a 5 s full-turn budget buys ~50,000.

ENUMERATION SIZE: joint full-turn enumeration is hopeless raw — ordered choice of 5 armies from N with ~11 targets each: for N=20 that's P(20,5) x 11^5 ≈ 3x10^11 sequences. Even one greedy step per level (sequential decomposition) reduces it to 5 x (N x 11) ≈ 1,100 node expansions ≈ 0.12 s — so sequential per-army decomposition with a beam is the only viable shape, and it fits comfortably.

FORWARD MODEL CORRECTNESS (verified by reading actions.ex, combat.ex, rng.ex, config.ex):
- Engine.move is pure ({game, result}); usable directly as the forward model. Combat (combat.ex resolve/3) is fully deterministic when battle_luck is off — and config.ex line 58 confirms battle_luck: false is the default. The luck/1 helper draws NO rng when the rule is off.
- RNG advances per battle regardless: 1 draw (sound, actions.ex:51) + 48 draws (battle_scar, actions.ex:116-130), purely cosmetic stream consumption. This is harmless for search: rng is an integer threaded deterministically through the state, so simulated lines are bit-exact futures of the current state, including any later battle-luck draws if that rule were on. Nothing hidden mutates; log/message strings are built per battle (minor cost, already in the 85 us).
- Caveat for transposition tables: identical board positions reached via different battle counts differ in game.rng, log, ai_trace, wait_support_*; a TT key must project those out. Move-order effects are real (party-wide morale hits use pre-battle loser counts; merges average morale), so genuine transpositions are rare — TT is low value here.

2-PLY FEASIBILITY: own-turn beam leaves can be scored with real opponent replies: Engine.end_turn + OriginalAi.perform_fast_ai_turn per opponent costs ~60 ms each (3 opponents = ~180 ms/leaf). 10 leaves = 1.8 s — slightly over budget as-is, but the 60 ms is 90% redundant pathfinding; a challenger-side reply policy using precomputed BFS distance fields runs the same greedy logic in ~5-10 ms/turn, making 10 leaves x 3 opponents ≈ 0.3 s. Full-width 2-ply (opponent replies inside the beam at every level) is NOT feasible; replies-at-leaves is.

MCTS ASSESSMENT: not recommended. Meaningful rollouts need whole opponent turns (60 ms with the baseline policy, still 5-10 ms optimized), giving only ~100-1000 rollouts/action — far too few for MCTS variance on a 220-hex 4-player game with 1e6-scale reward spikes (capital kills). Deterministic engine + deterministic opponent policy also means repeated rollouts of the same line add zero information; a beam with simulation-backed scoring extracts the same signal deterministically and cheaply.

### Recommendations

SEARCH SHAPE — beam over per-army sequential choices, simulation-backed, with opponent-reply evaluation at leaves:
1. Plan the WHOLE turn once at turn start (the engine is deterministic and it is the AI's own turn — nothing changes between its 5 actions, so plan once and execute the 5-move sequence; no per-action replanning needed).
2. Beam: state = game struct after k applied moves (apply via Engine.move — use it unmodified as the forward model). At each of up to 5 levels, for each beam state enumerate movable armies x possible_moves, pre-score with a FAST static eval, apply only the top-M candidates, keep top-W states. W=10, M=15 → ~750 Engine.move calls ≈ 80-110 ms per turn for the beam itself.
3. Leaf evaluation: for the top ~10 end-of-turn states, run Engine.end_turn then a cheap greedy reply for each living opponent (reimplement the baseline's ranking in the AI layer with cached distance fields — do NOT call OriginalAi in the hot loop) and score the resulting position: material/morale totals, capital threat (enemy power reachable onto our capitals in <=2 moves via ring2), cities held, capital-kill availability. ~0.3-0.5 s total.
4. Total: well under a 5 s turn budget with 2-4x headroom; degrade gracefully by shrinking W/M and skipping opponent replies (anytime scheme below).

DATA-STRUCTURE / SPEED TWEAKS (all in the challenger's namespace — the engine is frozen):
- Kill the pathfinding tax: once per turn, run one BFS per enemy capital over the 220 fields (respecting can_walk semantics) to get distance maps — ~1 ms total, replaces the baseline's ~12 ms/pass A* memo and makes static eval O(1) per candidate. This alone makes a challenger-side greedy scorer ~100x cheaper than rank_ai_armies.
- Reuse game.ring2 (precomputed 2-ring) for threat/support features, as OriginalAi does.
- Do NOT build a lite forward model initially: 85 us/move gives 10k sims/s which the beam doesn't saturate. If later needed (e.g., deeper opponent modeling), write an AI-layer apply that skips battle_scar/log/update_derived list rebuilds (~10 us achievable) and golden-test it against Engine.move on random positions — but treat as optional optimization, not architecture.
- Parallelism: beam levels are sequential, but candidate expansion and leaf-reply evaluation are embarrassingly parallel via Task.async_stream; keep it single-process first (fits budget), flip on async_stream for leaves if the server has spare cores.
- TT: skip (rng/log fields and real move-order effects make hits rare and keys awkward).

PER-MOVE TIME-BUDGET SCHEME (anytime, deadline-driven):
- Compute the greedy anchor first: one fast ranking pass (~1 ms with cached distances) yields a complete 5-move fallback plan immediately.
- Then run the beam with :erlang.monotonic_time deadline checks between expansions: spend <=40% of budget on the beam, <=50% on leaf opponent replies (evaluate leaves best-first so truncation keeps the most promising), reserve 10% slack. If the deadline hits at any point, emit the best complete plan found so far (worst case: the greedy anchor — never worse than baseline-shaped play).
- Serve each of the 5 actions from the cached plan in O(1); optionally re-verify each planned (from,to) against possible_moves before applying (cheap, 2.4 us) as a safety assert.
