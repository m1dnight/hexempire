# Hex Empire (Elixir + Phoenix LiveView)

A faithful port of the classic *Hex Empire* engine to Elixir, driven by a
Phoenix LiveView UI. The game logic is a **bit-exact reimplementation** of the
original JavaScript engine (in `original/`, not committed as a dependency —
reference only), verified by differential testing against the real thing.

## Run it

```bash
mix deps.get         # first time only
mix phx.server
```

Or as a container (see `Dockerfile`; CI builds it on every push to main):

```bash
docker build -t hexempire .
docker run -p 4000:4000 -e PORT=4000 -e PHX_HOST=localhost \
  -e SECRET_KEY_BASE=$(mix phx.gen.secret) \
  -v hexempire_saves:/var/lib/hex_empire/saves hexempire
```

> Note: `original/` and `harness/` (the original game's source and its Node
> golden-trace generator) are deliberately **not** committed — they contain
> proprietary code and stay local-only. CI needs only `test/golden/`.

Open <http://localhost:4000>. Tests: `mix test` (includes the full differential
suite — takes ~1 minute).

## How faithful is "faithful"?

The Elixir engine reproduces the original **bit for bit**:

* the SWF-era LCG (`seed*9301+49297 % 233280`) including its quirky non-Fisher-
  Yates shuffle — and every cosmetic RNG draw (background art, battle scars,
  war/gun sound picks) so the stream stays aligned,
* map generation (20×11 board, corner capitals, dilation, town spacing,
  port placement via the original's cursed generation pathfinder),
* combat (`count + morale` vs `count + morale`, ties to the defender,
  party-wide morale loss, winner casualties proportional to attacker count),
* per-army morale with faction-average derived morale, the totalCount/50
  morale floor, unmoved-army decay, annexation awards/penalties,
* capital fall → territory inherits to the captor, captured "province"
  capitals liberate with fresh 99/99 garrisons,
* reinforcements (`floor((lands + 5*ports)/producers)`), 5-move turns,
  distance-2 movement with ports enabling sea travel,
* and the complete original AI (capital gradients, wait-for-support with its
  load-bearing field-flag quirk, supporter moves, difficulty modifiers).

**Verification:** `test/golden/` holds traces generated by running the actual
original JS engine headlessly in Node (`harness/`). The test suite replays nine
complete AI-vs-AI games (~700 turns, three difficulties, human-flag variants)
and asserts the Elixir engine produces identical RNG state, armies, morale,
field ownership, and winners after every single turn — plus 722 combat vectors
and per-seed map/setup checks.

To regenerate golden data: `cd harness && node trace3.mjs <seed> <human> <difficulty>`.

## What's intentionally not ported

* **Cheats, alliances/pacts, speech, surrender** — the `cheats.js` module and
  the UI controller were missing from the source drop; their effect sizes are
  unrecoverable. All call sites treat them as absent (which matches defaults).
* **Capture-the-flag / domination modes, custom maps, fog** — generated maps
  carry no flags and fog is display-only; standard mode only.
* The original renderer/audio — the LiveView UI is our own (server-rendered
  SVG, no client game code).

## Deployment

Production runs the CI-built container on `hexempire-1` behind
`hexempire.call-cc.be`. Deploys are **pull-based**: a systemd timer on the
server (`hexempire-deploy.timer`, every 5 min) compares the running container's
image digest against `ghcr.io/m1dnight/hexempire:latest` and recreates the
container when CI has shipped something new — so a push to `main` is live
within ~10 minutes of the tests passing. Config lives in `/etc/hexempire.env`
(stable `SECRET_KEY_BASE` — sessions survive deploys); campaigns and matches
live in the `hexempire_saves` volume and survive container replacement.

## AI

Two AI players live in the engine:

* **`OriginalAi`** — the bit-exact port of the original's greedy scorer
  (golden-verified; this is what shipped games use).
* **`TurnPlannerAi`** — the challenger: deterministic beam search over the
  entire 5-move turn using the pure engine as its forward model, with BFS
  distance fields, a focus-target FFA policy, and ratio-gated combat
  (design + research in `docs/ai-research.md`). Tournament (200 games,
  seat-rotated, seeds 1-50): **53%** overall win rate vs the original's
  25% self-play null — stronger from every seat.

In the game, `TurnPlannerAi` is the **Brutal** difficulty: the fourth
option in the solo campaign selector, and a host-set "Computer strength"
toggle in match lobbies (classic is the default everywhere).

Measure any AI with `mix ai.tournament --games 50 --challenger <module>`;
the strength regression test runs with `mix test --only tournament`.

## Multiplayer

Click **Create multiplayer match** on the home page and share the `/m/<code>`
link. Friends claim factions in the lobby; unclaimed seats play as computers;
the host starts the match. Each claimed seat gets a **personal rejoin link**
(shown in the sidebar) that works from any device — matches are slow games,
persisted on disk, and happily span days. The engine runs multiplayer in the
original's spectator mode (`human: -1`): victory goes to the sole controller
of all four original capitals. Anyone with the plain link can watch.

## How to play

You are **Redosia** (red, top-left) by default — pick any faction and an AI
difficulty (Easy 0 / Normal 5 / Hard 10) under "New campaign".

* Click one of your armies, then a highlighted hex: yellow = move,
  red = attack, blue = merge. Armies move up to 2 hexes; ports let you embark.
* You get up to **5 moves per turn** (never more than your unmoved armies).
  The turn ends automatically when they're spent.
* Armies show **count** (big) and **morale** (★). Power = count + morale.
  Winning fights and taking towns raises morale; losses, lost towns, and
  idling lower it. Morale never exceeds count.
* Take an enemy **capital** to knock the faction out — its land falls to you.
  Capture **all** enemy capitals to win; lose yours and it's over.

## History

An earlier clean-room design document (`DESIGN.md`) was superseded when the
real game's source became available in `original/`; the engine is now a
bit-exact port of that code. Any mechanic question should be answered by
reading `original/*.js` or the matching module in `lib/hex_empire/engine/` —
they are line-for-line equivalent in behavior.

## Architecture

The engine core (`lib/hex_empire/engine/`) is **frozen and verified**: every
change must keep the golden replay suite green, and iteration order,
arithmetic, RNG draw order, and the documented quirks are load-bearing. All
callers reach it only through the `HexEmpire.Engine` facade (pure delegation
plus the game/field/army types). Above the engine, `HexEmpire.Campaigns` is
the session layer — it owns the human-move/AI-step orchestration and
persistence policy — backed by `HexEmpire.GameStore` (ETS cache + debounced,
version-tagged disk saves). `HexEmpireWeb.GameLive` is a thin LiveView shell:
socket assigns, the AI step timer, and server-rendered SVG. The game state is
a `%HexEmpire.Engine.Game{}` struct holding `%Field{}` structs (with embedded
`%Army{}` structs) — same shapes the original kept as JS objects.

## Layout

```
original/            reference JS source of the original game (read-only)
harness/             patched copy that runs the original engine in Node
                     (golden-trace generators: trace3.mjs, combat_vectors.mjs)
lib/hex_empire/
  engine.ex          HexEmpire.Engine — the facade (single public engine API)
  campaigns.ex       HexEmpire.Campaigns — session layer (moves, AI steps, saves)
  game_store.ex      HexEmpire.GameStore — ETS + disk persistence
lib/hex_empire/engine/   the bit-exact Elixir port (frozen — see Architecture)
  game.ex field.ex army.ex          state structs (%Game{}, %Field{}, %Army{})
  rng.ex config.ex hex.ex generator.ex pathfinding.ex movement.ex
  morale.ex combat.ex territory.ex reinforcements.ex
  state.ex actions.ex original_ai.ex city_names.ex
lib/hex_empire/matches*      multiplayer: context, per-match GenServer, store
lib/hex_empire_web/live/     game_live.ex (solo), match_live.ex (multiplayer)
lib/hex_empire_web/components/board_components.ex  shared SVG board (styles in assets/css/app.css)
test/golden/         golden vectors + full-game traces from the original
test/hex_empire/engine/  differential test suite
```
